# Подключение Supabase

## 1. Применить схему

Откройте Supabase Dashboard нужного проекта, перейдите в **SQL Editor → New query**, вставьте содержимое `supabase/schema.sql` и нажмите **Run**. Скрипт создаст таблицы, политики доступа, bucket для QR и начальные карточки/курсы. Таблица `site_settings` хранит редактируемые настройки футера.

Если проект уже запущен, повторно выполните актуальный `supabase/schema.sql`: он явно отзывает у `anon` и `public` все права на таблицы, затем выдаёт только необходимые права. Это важно для защиты заявок даже при оставшихся старых GRANT.

Для проверки прав выполните:

```sql
select
	has_table_privilege('anon', 'public.applications', 'select') as anon_can_read_applications,
	has_table_privilege('anon', 'public.applications', 'insert') as anon_can_submit_applications;
```

Ожидаемый результат: `anon_can_read_applications = false`, `anon_can_submit_applications = true`.

## 2. Создать учётную запись администратора

В Supabase откройте **Authentication → Users → Add user** и создайте пользователя с email и сильным паролем. Подтвердите email, если это требуется настройками проекта.

Скопируйте UUID пользователя из списка Auth Users. В SQL Editor выполните команду, заменив UUID:

```sql
insert into public.admin_users (user_id)
values ('UUID-ПОЛЬЗОВАТЕЛЯ-ИЗ-AUTH-USERS');
```

После создания администратора отключите публичную регистрацию пользователей в **Authentication → Settings → User Signups**. Не удаляйте auth-пользователя, пока он связан с записью в `admin_users`.

## 3. Проверить клиентские настройки

`scripts/config.js` содержит Project URL и публичный Publishable key. Project URL имеет формат `https://<project-ref>.supabase.co`. Для браузера разрешён только ключ `sb_publishable_...` (или старый публичный `anon`). Ключ `sb_secret_...` / `service_role` нельзя помещать в файлы сайта, GitHub или настройки Pages.

Если secret key ранее отправлялся в переписке или коммитился, отзовите его в Supabase API Keys и выпустите новый. Для работы этой клиентской версии secret key не требуется.

## 4. Опубликовать

После изменения файлов запушьте изменения в GitHub и дождитесь успешного deploy в Cloudflare Pages. Войдите на сайт двойным кликом по логотипу, используя email и пароль Auth-пользователя. Страница `admin_panel.html` дополнительно проверит запись пользователя в `admin_users`.

## Возможности

- В админке редактируются, скрываются, добавляются, удаляются и перемещаются карточки преимуществ, FAQ и курсов; для футера доступны бренд, описание, ссылки, контакты и соцсети.
- У курса есть категория, цена, описание, программа, инструкция, ссылка или загружаемый Kaspi QR. Его публичная страница открывается как `course.html?slug=basic`.
- Заявки можно искать по ФИО/телефону, сортировать, отмечать просмотренными при переходе в WhatsApp и отдельно менять ручной статус оплаты.
- Уведомление от Supabase о новой заявке и серверное ограничение частоты отправок пока не настроены. Honeypot в форме помогает только от простых ботов; перед активной рекламой следует добавить Cloudflare Turnstile и серверную проверку.
